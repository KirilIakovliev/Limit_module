# Миграция frontend на React

Аудит текущего UI и план замены. API, SQL и бизнес-контракты не меняются. Канонический документ: этот файл.

Дата фиксации версий: 2026-10-09, registry `https://registry.npmjs.org/`, Node на машине планирования `v20.19.4`.

## 1. As-Is

Один HTML-экран [`web/index.html`](../web/index.html) и 9 IIFE-скриптов (около 1 800 строк JS, 656 строк CSS). Отдельных URL у разделов нет. FastAPI монтирует каталог `WEB_DIR` (по умолчанию `/srv/web`) через `StaticFiles(..., html=True)` на `/`, если в нём есть `index.html` ([`api/app/main.py`](../api/app/main.py)). API и страница — один процесс `:8000`. Авторизации нет. CORS `*`. Redis кэширует только `GET /api/meta` (TTL 60 с). Браузер к Redis не ходит.

Клиент — [`web/js/api.js`](../web/js/api.js):

| Метод | Назначение |
|---|---|
| `GET /api/health` | БД, наличие витрин, `web_mounted` |
| `GET /api/meta` | `updated_at`, `data_date`, `stale`, `stale_after_hours` |
| `GET /api/clients?q=&limit=8` | Подсказки, минимум 3 символа на сервере |
| `GET /api/clients/{inn}` | Карточка |
| `GET /api/clients/{inn}/limits` | Лимиты, заявки, единые показатели |
| `GET /api/groups/{crmId}` | Карточка ГК |

`window.APP_CONFIG.apiBase` читается, в HTML не задаётся. База по умолчанию `/api`.

`index.html` подключает Manrope и Inter с `fonts.googleapis.com`. В закрытом контуре этот запрос не выполняется. Файлов шрифтов в репозитории нет.

Деньги в JSON — строки (`Money` в [`api/app/models.py`](../api/app/models.py)). Даты на экране форматируются из `YYYY-MM-DD` без `Date`, чтобы не сдвигать день. ИНН — строка.

Тесты UI: [`tools/verify_build.py`](../tools/verify_build.py) проверяет наличие строк в исходниках. Pytest покрывает API и SQL, не браузер. CI нет.

[`Dockerfile.prod`](../Dockerfile.prod) копирует `web/` как есть. Node в runtime-образе нет. Python-зависимости ставятся из Artifactory. Helm и nginx проксируют весь `/` на uvicorn.

## 2. Functional inventory

Один экран, состояния внутри JS.

- **Поиск.** Имя или ИНН, debounce 160 мс, до 8 подсказок, клавиатура, подсветка через `Format.normalize`. «Поиск» активен только после выбора строки. 503 — «витрины не загружены». Код: `search-bar.js`.
- **Карточка.** `Promise.all` клиента и лимитов. Обработка, ошибка, повтор, «Новый поиск». На старте `health`: если `marts === false`, сразу ошибка. Переход из ГК запрашивает карточку заново.
- **Актуальность.** После загрузки `GET /api/meta`. Сегодня — время, иначе дата и время. `stale` — предупреждение. Код: `app.js`.
- **Уровень 1.** «Компания», статичные ИНН и КПП, «События» с пометкой «(в разработке)». Повторный клик сворачивает. Геометрия `fitTopRow` / `layoutBranch` — вёрстка текущего экрана, не контракт данных.
- **Основная информация.** Имя, ИНН, ОГРН, КПП, адрес, ОКВЭД, имя ГК. Поля `code`, `source`, `groups_found` на экран не выводятся.
- **Группа.** Ленивый `GET /api/groups/{crm_id}`. Валюты не суммируются. Участники схлопываются по ИНН. Текущая компания без перехода. `has_card === false` — «карточки нет». «Крышка» — «нет данных». Лист Excel группы есть только если карточка ГК уже загружена.
- **Лимиты.** Блоки по подряд идущему `owner`. Колонки из `table-views.js`. «№ договора» и «Дата решения» всегда «—». `is_exceeded` подсвечивает строку. Блок `unified` по валютам. Заявки — отдельный блок под таблицей.
- **Сублимиты и резервы.** Текст «Источник данных не подключён». Endpoint нет.
- **События.** Считаются в браузере (`events.js`). На payload `{profile, limits}` работает только ветка лимитов: утилизация ≥100% — critical, ≥90% — warning, `end_date` в ближайшие 90 дней — warning. Фильтры critical / warning / positive. В Excel не входят. Ветки показателей и резервов в коде есть, данных для них нет. Spec [`specs/2026-09-29-group-currency-layout.md`](../specs/2026-09-29-group-currency-layout.md) оставляет эти правила.
- **Excel.** Листы: Компания, Группа компаний (если открыта), Лимиты, Заявки (если не пусто). ИНН текстом. Имя `АББ_{inn}_{YYYY-MM-DD}.xlsx`. ZIP пишет самописный `xlsx-writer.js`.

Переписать визуал. Перенести чистыми функциями: формат, события, состав листов, группировку лимитов по соседнему `owner`, свёртку участников ГК, гонку подсказок, порог 3 символов, обязательный выбор из списка, подпись свежести, тексты 503.

## 3. Макет и покрытие API

В [`context/design_samples/`](../../context/design_samples/) один файл: `limits_tab.png`. Каталог `context/` в git репозитория не входит. Других экранов в макетах нет. Цифры и названия на PNG — образец рисунка, не ответ API.

Макет — карточка компании на вкладке «Лимиты»: шапка (название, ИНН, КПП, счётчик событий), вкладки, панель действий, карточка «Единый лимит», таблицы по владельцам.

## 4. Target architecture

### Стек

Mantine, не shadcn/ui: shadcn собирается на Tailwind, стили проекта — CSS Modules и токены. Mantine темизируется CSS-переменными и не заводит вторую систему стилей.

Версии — последние стабильные, которые одновременно совместимы друг с другом и с Node 20.19. Mantine 7 не используется: актуальная стабильная линия — 9.7.1 (peer `react@^19.2.0`).

| Пакет | Версия | Почему не «самый старший номер» |
|---|---|---|
| `react`, `react-dom` | 19.3.0 | Текущий стабильный. Удовлетворяет peer Mantine |
| `typescript` | 6.0.3 | Старший выпуск, который принимает `typescript-eslint@8.71.1` (`typescript <6.1`). TypeScript 7.0.2 опубликован, линтер его не поддерживает |
| `vite` | 8.3.4 | Текущий стабильный, engines `^20.19.0 \|\| >=22.12.0` |
| `@vitejs/plugin-react` | 6.1.2 | Peer `vite@^8` |
| `@mantine/core`, `@mantine/hooks` | 9.7.1 | Текущая стабильная линия |
| `react-router` | 7.18.4 | 8.4.0 требует Node `>=22.22.0`. На Node 20.19 ставится 7.18.4, пакет `react-router-dom` с v7 не нужен |
| `@tanstack/react-query` | 5.104.1 | Актуальный адаптер для React. Линия 6 — не React-адаптер |
| `vitest` | 4.1.11 | 5.0.3 требует Node `^22.12.0`. 4.1.11 работает на Node 20 и с Vite 8 |
| `jsdom` | 29.1.1 | Текущий стабильный с engines `^20.19.0` |
| `eslint` | 10.12.0 | Текущий стабильный, engines включают Node `^20.19.0` |
| `typescript-eslint` | 8.71.1 | ESLint 10 и TypeScript `<6.1` |
| `eslint-plugin-react-hooks` | 7.1.1 | ESLint 10 |
| `@testing-library/react` | 16.3.3 | React 19 |
| `@testing-library/jest-dom` | 6.9.1 | 6.10 и 7 требуют Node `>=22`. 6.9.1 — последняя линия с Node 20 |

`eslint-plugin-react@7.37.5` не ставится: peer ограничен ESLint `^9.7`. JSX проверяет TypeScript, хуки — `eslint-plugin-react-hooks`.

На этапе инфраструктуры не ставятся TanStack Table, Zod, `exceljs`, генератор OpenAPI. Они нужны следующим этапам, не каркасу.

Сборка пишет в `frontend/dist/`. Каталог `web/next/` этим шагом не заполняется. Перенос — отдельная команда `npm run publish:next`: копия во временный `web/.next-staging`, проверка, замена только `web/next/`. Скрипт отказывается работать, если цель — не `web/next`, и сверяет хеши `web/index.html`, `web/js/app.js`, `web/css/styles.css` до и после. Оба каталога в `.gitignore`.

Runtime-образ остаётся Python. В `index.html` сборки нет внешних URL. Шрифты на этапе каркаса — системный стек в токенах. Файлы шрифтов появятся вместе с макетом, не с CDN.

### Каталоги

```text
frontend/
  index.html
  package.json
  package-lock.json
  vite.config.ts          # base /next/, outDir dist, proxy /api
  eslint.config.js
  tsconfig.json
  scripts/publish-next.mjs
  src/
    main.tsx
    app/App.tsx
    app/providers.tsx     # QueryClient, MantineProvider
    app/routes.tsx        # единственный список маршрутов
    app/router.tsx        # basename из Vite base
    styles/tokens.css     # заглушки токенов, не палитра макета
    styles/global.css
    features/shell/       # пустая оболочка, не экран лимитов
    test/setup.ts
```

Пустые каталоги `api/`, `lib/`, экранов лимитов и поиска не создаются, пока нет переноса.

### Маршруты и SPA fallback

Сейчас один маршрут `/` внутри `basename`. Новые экраны добавляются в `src/app/routes.tsx`. `basename` считается из `import.meta.env.BASE_URL`: Vite `base` сейчас `/next/`, при финальной сборке — `/` через `VITE`/`base`, без правки роутера.

`StaticFiles(html=True)` отдаёт `index.html` только для каталога. Путь вида `/next/company/123` получит 404, пока нет fallback. Пока единственный маршрут совпадает с каталогом `/next/`, fallback не нужен и в FastAPI не добавляется.

При первом вложенном маршруте или при переключении корня на новую сборку раздача меняется точечно: GET без файла и вне `/api`, `/docs`, `/openapi.json`, `/redoc` возвращает `index.html` активной сборки. До этого `main.py` не трогается. Откат — не публиковать `web/next/` или не открывать `/next/`; старый `/` остаётся `web/index.html`.

### Dev

`npm run dev` — Vite, `base: /next/`, proxy `/api` → `http://127.0.0.1:8000`. Продакшен-проверка `/next/` — собранный `dist`, затем `publish:next`, отдача тем же FastAPI, что и старый UI.

## 5. Migration roadmap

1. **Инфраструктура.** Каркас из раздела 4, strict TypeScript, ESLint, Vitest, smoke-тест оболочки, production-сборка в `frontend/dist/`, отдельно `publish:next`. Критерий: `tsc`, lint, test, build зелёные; `/` и `/next/` открываются; в HTML сборки нет внешних URL; старые файлы `web/` не изменены. Страницы, API-клиент и бизнес-логика не переносятся.
2. **API-клиент.** Снимок OpenAPI, генерация типов, хуки Query на шесть существующих GET. Тесты клиента на разбор 404/503 и типы `Money` как `string | null` — в том же изменении. Критерий: хуки не вызывают других URL.
3. **Дизайн-система.** Токены заменяются значениями макета, локальные шрифты, тема Mantine читает токены. Геометрия старого `tab-tree.js` не переносится. Критерий: страница не запрашивает внешние хосты. Палитру не выдумывать до макета; сейчас есть только `limits_tab.png`.
4. **Эталон — вкладка «Лимиты».** Только элементы, которые макет и API покрывают вместе (таблица раздела 3). Пробелы (совокупный лимит, календарь среза, EN, меню строки, «закрытые») не реализуются, пока нет решения в открытых вопросах. Вместе с экраном: Vitest на группировку по соседнему `owner` и формат денег/дат; Testing Library на таблицу, пустое состояние и 503. Критерий: тесты эталона зелёные до начала следующего экрана.
5. **Остальные экраны.** По одному, каждый со своими тестами до перехода к следующему. Порядок после лимитов — когда есть макет или явное решение переносить текущее поведение без макета. Поиск, ГК, события, заглушки, Excel не начинать пакетом.
6. **Паритет.** Сверка с фикстурами Ростелеком / ВТБ / МТС-Банк по чеклисту раздела 2 для уже перенесённых экранов. Playwright — когда есть сценарий кликов, не в каркасе. Pytest и `verify_build.py` не менять до удаления старого UI.
7. **Production.** `npm ci` и `npm run build` на машине с Node. В образ копируется уже собранный `frontend/dist` (после переключения — как корень статики, до него — результат `publish:next` в `/srv/web/next`). Runtime без Node. Критерий: `/` старый, `/next/` новый, `/api/health` прежний, внешних URL в HTML нет.
8. **Удаление старого UI.** После приёмки. Удалить `web/js`, `web/css`, старый `index.html`, собрать с `base: /`, включить SPA fallback, обновить `verify_build.py` и README.

## 6. Risks

- Google Fonts в старом HTML в контуре не грузятся. Новый бандл должен быть самодостаточным. На каркасе шрифт системный, это не финальный вид.
- Вложенный маршрут без fallback на FastAPI даст 404. Fallback включается отдельным изменением раздачи, не вместе с каркасом.
- Копирование сборки мимо `web/next/` может затереть старый UI. `publish:next` режет любую другую цель и проверяет хеши трёх файлов старого UI.
- `exceljs` на будущем этапе меняет байты xlsx. Сравнивать листы, не ZIP. `xlsx-writer.js` не переносить.
- Правила событий зависят от текущей даты. Тесты фиксируют «сегодня» в момент переноса `events.js`.
- Сборка frontend на стенде требует npm-registry. Python-образ пакеты npm не ставит. Локально использован публичный `registry.npmjs.org`. Зеркало Artifactory для npm в репозитории не задано.
- `verify_build.py` покраснеет, если править старые файлы `web/` до шага 8.
- Макет не покрывает текущую функциональность целиком. Реализация «как на картинке» без сверки с разделом 3 добавит поля, которых API не отдаёт.

## 7. Open questions

- «Совокупный лимит» на карточке компании: ждать новое поле API или убрать с экрана? `GroupSummary.total_limit` для этой ячейки не использовать.
- «Показывать закрытые лимиты»: это клиентский фильтр `status_code == inactive` или другой признак, которого в контракте нет?
- Календарь «Дата» — элемент без данных. Нужен новый параметр API или контрол убирается до появления срезов?
- Переключатель EN — в объёме первой версии или отложен?
- Вкладка «Сублимиты» текущего UI на макете отсутствует. Её сохранять заглушкой или не переносить, пока нет макета и API?
- Содержимое вкладок «Общая информация», «Лимиты на рассмотрении», «Резервы» и экрана поиска не нарисовано. До макетов переносить текущее поведение или ждать рисунок?
- Где выполнять `npm ci` для образа стенда и какой внутренний npm-registry, если публичный `registry.npmjs.org` в контуре закрыт?
- Нужен ли переход на Node 22, чтобы позже взять React Router 8 и Vitest 5? Сейчас это не блокер: зафиксированы совместимые 7.18.4 и 4.1.11.
