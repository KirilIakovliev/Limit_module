```python
import os
from contextlib import asynccontextmanager

from fastapi import FastAPI
from psycopg_pool import ConnectionPool
from psycopg.rows import dict_row

DATABASE_DSN = os.getenv("DATABASE_URL", "postgresql://abb:abb@db:5432/abb")
db_pool = ConnectionPool(DATABASE_DSN, min_size=1, max_size=10,
                         open=False, kwargs={"row_factory": dict_row})

@asynccontextmanager
async def lifespan(app: FastAPI):
    db_pool.open()
    db_pool.wait(timeout=30)
    yield
    db_pool.close()

app = FastAPI(lifespan=lifespan)

def db_query(sql, params=()):
    with db_pool.connection() as conn, conn.cursor() as cur:
        cur.execute(sql, params)
        return cur.fetchall()

@app.get("/api/companies")
def search_companies(q: str, limit: int = 8):
    return db_query(
        "SELECT id, name, inn, kpp, industry FROM companies "
        "WHERE is_active AND name ILIKE %(like)s ORDER BY name LIMIT %(limit)s",
        {"like": f"%{q}%", "limit": limit},
    )
```

Запуск и проверка:

```bash
curl -s "localhost:8000/api/companies?q=маг"
```


**Как это соединено с шагом 1:** строка SQL внутри `db_query` — единственное

Три вещи, которые здесь сцепляются с другими файлами:

| В HTML | Кто это использует |
|---|---|
| `id="searchInput"` | `search-bar.js`: `document.getElementById('searchInput')` |
| `class="search-field"` | `styles.css`: правило `.search-field { ... }` |
| `<script src="js/api.js">` | порядок загрузки: `api.js` должен идти до `search-bar.js` |

**Это и есть главный стык HTML ↔ CSS ↔ JS: `id` — для скриптов, `class` — для
стилей.** Правило не абсолютное, но полезное: если стилизовать по `id`,
переиспользовать стиль не выйдет; если искать элементы по классу, случайное
переименование в CSS сломает скрипт.

геометрия (`transform`, `--tab-min`), которую нельзя выразить статическим
правилом.

### Шаг 5. Клиент API

```javascript
const API = (() => {
  const BASE = '/api';

  async function call(path) {
    const res = await fetch(BASE + path, { headers: { Accept: 'application/json' } });
```

### Шаг 6. Поведение поля ввода

`web/js/search-bar.js`:

```javascript
const SearchBar = (() => {
  const input = document.getElementById('searchInput');
  const dropdown = document.getElementById('suggestionList');
  const submitButton = document.getElementById('searchButton');

  let suggestions = [];
  let selectedCompany = null;
  let requestCounter = 0;
  let debounceTimer = null;

  const callbacks = { submit: () => {} };

  input.addEventListener('input', () => {
    const text = input.value.trim();
    clearTimeout(debounceTimer);
    if (text.length < 3) { dropdown.classList.remove('is-open'); return; }
    debounceTimer = setTimeout(() => loadSuggestions(text), 160);
  });

  async function loadSuggestions(text) {
    const requestId = ++requestCounter;
    const result = await API.searchCompanies(text);
    if (requestId !== requestCounter) return;      // ответ устарел
    suggestions = result;
    render();
  }

  function render() {
    dropdown.innerHTML = suggestions.map((company, i) => `
      <div class="suggestion" data-index="${i}">
        <span class="suggestion-name">${company.name}</span>
        <span class="suggestion-meta">ИНН ${company.inn}</span>
      </div>`).join('');

    dropdown.querySelectorAll('.suggestion').forEach(node => {
      node.addEventListener('mousedown', event => {
        event.preventDefault();
        selectCompany(suggestions[+node.dataset.index]);
      });
    });

    dropdown.classList.add('is-open');
  }

  function selectCompany(company) {
    selectedCompany = company;
    input.value = company.name;
    dropdown.classList.remove('is-open');
    submitButton.disabled = false;
  }

  submitButton.addEventListener('click', () => {
    if (selectedCompany) callbacks.submit(selectedCompany);
  });

  return { onSubmit: fn => { callbacks.submit = fn; } };
})();
```

Разберём стыки построчно:

1. `getElementById('searchInput')` ← `id` из шага 3.
2. `API.searchCompanies` ← модуль из шага 5.
3. `dropdown.classList.add('is-open')` ← класс из шага 4.
4. `data-index="${i}"` — кладём номер в разметку, читаем через `node.dataset.index`.
   `+` перед ним превращает строку в число: атрибуты всегда строки.
5. `callbacks.submit` — модуль не знает, что произойдёт после нажатия. Он
   объявляет событие, а решение принимает `app.js`. Это **инверсия
   зависимостей**: поиск не зависит от дерева вкладок.

**Состояние:** подсказки работают, кнопка «Поиск» активируется после выбора.

```javascript
const Format = (() => {
  const nf = (min, max) => new Intl.NumberFormat('ru-RU', {

  });

  const rub = v => v == null ? '—' : nf(0, 0).format(Math.round(v)) + ' ₽';
```

## Часть II. Как слои связаны: четыре шва

Полезнее помнить не файлы, а **швы** — места, где слои соприкасаются. Их
ровно четыре, и каждый ломается по-своему.

### Шов 1: HTML ↔ CSS (класс)

```html
<div class="suggestions" id="suggestionList">
```
```css
.suggestions { display: none; }
.suggestions.is-open { display: block; }
```

Ломается тихо: переименовали класс в одном месте — стиль просто перестал
применяться, ошибок в консоли нет. Диагностика: инспектор браузера, вкладка
Styles — видно, какие правила применились и какие перечёркнуты.

### Шов 2: HTML ↔ JS (идентификатор)

```html
<input id="searchInput">
```
```javascript
const input = document.getElementById('searchInput');
```

Ломается громко: `null`, а следом `Cannot read properties of null`.
Частая причина — скрипт выполнился до появления элемента.

### Шов 3: JS ↔ API (адрес и форма ответа)

```javascript
call(`/companies?q=${encodeURIComponent(q)}&limit=8`)
```
```python
@app.get("/api/companies")
def search_companies(query: str = Query(..., alias="q", min_length=3), limit: int = 8):
```

Ломается видимо: 404 (не тот путь), 422 (не тот параметр), 500 (упал сервер).
Диагностика: вкладка Network в браузере — там виден и запрос, и ответ.

Тонкость: совпадать должны не только адреса, но и **имена полей в ответе**.
API отдаёт `limit_amount` — интерфейс читает `item.limit_amount`. Переименуете
поле в SQL — получите `undefined` в таблице, без единой ошибки.

### Шов 4: API ↔ база (SQL и типы)

```python
db_query("SELECT id, name, inn FROM companies WHERE ...")
```

Ломается громко: `UndefinedColumn`, `UndefinedTable`. Наш случай:
`column "search_name" does not exist`, потому что миграция не применилась.

```python
@app.get("/api/companies/{company_id}/limits")
def company_limits(company_id: int):
    rows = to_jsonable(db_query(
        """SELECT id, block, product, status, currency,
                  limit_amount, used_amount,
                  limit_amount - used_amount AS available,
                  total_limit, utilization_cap_pct, valid_until
           FROM limits WHERE company_id = %s
           ORDER BY block, limit_amount DESC""",
        (company_id,),
    ))

    blocks = [
        {"code": code, "title": title, "items": [r for r in rows if r["block"] == code]}
        for code, title in BLOCK_TITLES.items()
    ]
    total = sum(r["limit_amount"] for r in rows)

    return {
        "blocks": [b for b in blocks if b["items"]],
        "unified": {"sublimit": total, "utilized": used, "available": total - used},
```

структуры — делает API.

### Демонстрация: та же компания на всех семи файлах

Смотрим на «Магнитогорский МК» и на то, во что превращаются его данные.

**1. База** — плоские строки:

```sql
SELECT block, product, limit_amount, used_amount FROM limits WHERE company_id = 2 LIMIT 3;
```

```
   block    |          product           | limit_amount | used_amount
------------+----------------------------+--------------+-------------
 corporate  | Торговое финансирование    | 928374651.00 | 401197496.00
 corporate  | Банковские гарантии        | 898123400.00 | 347962504.00
 investment | Синдицированный кредит     | 200106500.00 |  92048990.00
```

**2. API** — та же выборка, сгруппированная и досчитанная:

```json
{
  "blocks": [
    {"title": "Корпоративный блок",  "items": 5},
    {"title": "Инвестиционный блок", "items": 2}
  ],
  "unified": {
    "sublimit":  4132423457.79,
    "utilized":  1807117974.18,
    "available": 2325305483.61
  },
  "applications": 3
}
```

`unified.sublimit` — сумма всех семи лимитов. В базе такого поля нет.

**3. Вкладка** — из этого же ответа берётся подпись:

```javascript
value: Format.compact(limits.total),      // «4,13 млрд ₽»
note: `утилизация ${utilization}%`,       // «утилизация 43,7%»
```

**4. Экран** — `TableViews.limits` строит две таблицы и три карточки.

**5. Выгрузка** — те же данные попадают в Excel:

```
листы: ['Компания', 'Группа компаний', 'Баланс', 'Финрезультаты',
        'Коэффициенты', 'Лимиты', 'Заявки на рассмотрении',
        'Сублимиты', 'Информация о резервах']

ячейка D5: 401197496 | тип: n (n = число) | формат: #,##0
```

**Итог.** Одни и те же числа прошли через SQL → словари Python → JSON →
объекты JavaScript → HTML → XML внутри ZIP. Ни на одном шаге они не
дублируются в хранилище: единственная копия живёт в Postgres, всё остальное —
представления, которые собираются заново на каждый запрос.

## Проверьте себя

Ответы скрыты — сначала попробуйте сформулировать свой.

**1. Почему `api.js` вынесен в отдельный файл, хотя `fetch` можно вызвать прямо из `search-bar.js`?**

<details>
<summary>Показать ответ</summary>

Чтобы адрес и формат общения с сервером жили в одном месте. Сменится префикс
`/api`, добавится заголовок авторизации, понадобится fallback на демо-данные —
правка будет в одном файле, а не в шести.

</details>

**2. Что произойдёт, если подключить `search-bar.js` раньше `api.js`?**

<details>
<summary>Показать ответ</summary>

При загрузке ошибки не будет: `SearchBar` только объявит функции. Но при первом
вводе трёх символов вызов `API.searchCompanies` упадёт с `API is not defined`,
потому что к этому моменту переменная ещё не создана. Обычные скрипты
выполняются строго по порядку подключения.

</details>

**3. Почему JS переключает классы, а не пишет стили напрямую?**

<details>
<summary>Показать ответ</summary>

Внешний вид остаётся в CSS, поведение — в JS. Дизайнер меняет анимацию, не
трогая скрипт. Плюс переключение класса — одна операция, а не набор
присваиваний, и её легко отменить. Исключение — вычисляемая геометрия
(`transform`, `--tab-min`), которую нельзя выразить статическим правилом.

</details>

**4. Модуль `SearchBar` не знает, что произойдёт после нажатия «Поиск». Как это устроено и зачем?**

<details>
<summary>Показать ответ</summary>

Через колбэк: `SearchBar.onSubmit(fn)` сохраняет функцию, а модуль вызывает её
в нужный момент. Так поиск не зависит от дерева вкладок — его можно
переиспользовать или тестировать отдельно. Решение о том, что делать дальше,
принимает `app.js`, который видит всю картину.

</details>

**5. В таблице вместо суммы отображается «undefined». По какому шву искать?**

<details>
<summary>Показать ответ</summary>

Шов 3 — имена полей. Скорее всего, API отдаёт `limit_amount`, а код читает
`item.amount` (или наоборот). Откройте вкладку Network, посмотрите настоящий
JSON ответа и сравните ключи. Ошибки в консоли при этом не будет: обращение к
несуществующему полю объекта в JavaScript законно.

</details>

**6. Почему `available` считается в SQL, а `unified` — в Python?**

<details>
<summary>Показать ответ</summary>

`available = limit_amount - used_amount` — арифметика внутри строки, база
делает это бесплатно и точно, в типе `NUMERIC`. `unified` требует
перегруппировки строк в структуру `{blocks, unified, applications}` — это уже
про форму ответа, то есть зона ответственности API.

</details>

**7. Что сломается, если убрать `position: relative` у `.search-area`?**

<details>
<summary>Показать ответ</summary>

Выпадающий список с `position: absolute` начнёт позиционироваться относительно
ближайшего позиционированного предка выше по дереву — вплоть до `<body>`. Он
уедет в угол страницы. Пара «родитель relative + ребёнок absolute» — базовая
связка позиционирования.

</details>

**8. Вы добавили поле в API, но на экране его нет. Порядок диагностики?**

<details>
<summary>Показать ответ</summary>

Снизу вверх по швам: (1) `curl` к эндпоинту — есть ли поле в JSON; если нет,
проблема в SQL или в функции API. (2) Вкладка Network — тот ли ответ дошёл до
браузера, не отдаётся ли старая версия из кэша. (3) Консоль — нет ли ошибки в
рендере. (4) Версия ресурсов `?v=` и жёсткая перезагрузка.

</details>

**9. Зачем `pointer-events: none` у скрытой панели результатов?**

<details>
<summary>Показать ответ</summary>

`opacity: 0` делает элемент невидимым, но он остаётся на месте и продолжает
перехватывать клики. Прозрачная панель поверх страницы блокировала бы
взаимодействие с тем, что под ней.

</details>
