# Лекция 5. Бэкенд: Python, FastAPI и работа с базой

## 5.1. Что делает бэкенд

Три обязанности:

1. Принять HTTP-запрос и понять, чего просят.
2. Сходить в базу, получить данные, привести их к нужной форме.
3. Отдать JSON.

Плюс у нас — раздача файлов фронтенда и применение миграций при старте.
Весь бэкенд — один файл `api/app/main.py` (~500 строк) плюс `cache.py`.
Для проекта такого размера дробить на пакеты преждевременно; ориентир для
разделения — когда файл перестаёт помещаться в голову, примерно 700–1000 строк.

## 5.2. Минимум Python

```python
def db_query(sql: str, params: tuple = ()) -> list[dict]:
    ...
```

- `def` — объявление функции
- `sql: str` — **аннотация типа**. Python её не проверяет, но FastAPI и
  редактор используют
- `params: tuple = ()` — значение по умолчанию
- `-> list[dict]` — что возвращает

```python
rows = [{k: to_float(v) for k, v in r.items()} for r in rows]
```

Вложенное включение (comprehension): для каждой строки построить новый словарь,
пропустив значения через функцию. Читается справа налево: «для каждого `r` из
`rows` … для каждой пары `k, v` из `r.items()`».

```python
if (hit := response_cache.get("meta")) is not None:
    return hit
```

`:=` — «морж», присваивание внутри условия. Экономит строку.

```python
{**to_jsonable(head)[0], "members": members}
```

`**` разворачивает словарь в другой словарь — получаем копию с добавленным
полем.

## 5.3. FastAPI: маршруты

```python
from fastapi import FastAPI, HTTPException, Query

app = FastAPI(title="Лимитный модуль АББ", version="0.2.0", lifespan=lifespan)

@app.get("/api/companies/{company_id}/limits")
def company_limits(company_id: int):
    ...
```

- `@app.get(...)` — **декоратор**: регистрирует функцию как обработчик GET по
  этому пути
- `{company_id}` — переменная часть пути; попадает в одноимённый аргумент
- `company_id: int` — FastAPI сам преобразует строку из URL в число, а если не
  получится, вернёт понятную ошибку 422. Ручной валидации писать не нужно

Параметры из query string:

```python
@app.get("/api/companies")
def search_companies(query: str = Query(..., alias="q", min_length=3), limit: int = 8):
```

- `alias="q"` — в URL параметр называется `q`, в коде переменная `query`
- `...` (Ellipsis) — параметр обязателен
- `min_length=3` — короче трёх символов запрос не примут

Ошибки:

```python
if not rows:
    raise HTTPException(404, "Компания не найдена")
```

FastAPI превратит это в ответ `404` с телом `{"detail": "Компания не найдена"}`.

Бонус: по адресу `/docs` автоматически доступна интерактивная документация —
её строит FastAPI из аннотаций типов.

## 5.4. Подключение к базе

```python
from psycopg_pool import ConnectionPool
from psycopg.rows import dict_row

db_pool = ConnectionPool(DATABASE_DSN, min_size=1, max_size=10,
                         open=False, kwargs={"row_factory": dict_row})
```

> **Где это в коде:** `api/app/main.py:20` — создание пула;
> `api/app/main.py:115` — функция `db_query`.

**Пул соединений.** Установка соединения с Postgres стоит миллисекунды и
ресурсы. Пул держит их наготове и выдаёт по требованию. `max_size=10` — десяти
соединений хватает на сотню пользователей: каждый запрос держит соединение
2 мс, остальное время оно свободно.

`row_factory=dict_row` — возвращать строки словарями (`row["name"]`), а не
кортежами (`row[1]`). Код становится читаемым.

```python
def db_query(sql: str, params: tuple = ()) -> list[dict]:
    with db_pool.connection() as conn, conn.cursor() as cur:
        cur.execute(sql, params)
        return cur.fetchall()
```

`with` — контекстный менеджер: соединение возвращается в пул автоматически,
даже если внутри произошла ошибка. Без него утечка соединений — вопрос времени.

### SQL-инъекции

**Никогда не склеивайте SQL из строк:**

```python
cur.execute(f"SELECT * FROM companies WHERE inn = '{user_input}'")   # ОПАСНО
```

Если ввести `' OR '1'='1`, условие станет всегда истинным. Правильно:

```python
cur.execute("SELECT * FROM companies WHERE inn = %s", (user_input,))
```

Драйвер передаёт значение отдельно от текста запроса, и оно не может стать
частью команды. У нас так везде — обратите внимание на именованные параметры:

```python
db_query(PREFIX_SQL, {"q": query.lower(), "prefix": f"{query.lower()}%", "limit": limit})
```

В SQL они выглядят как `%(prefix)s`. И отдельная тонкость: **знак процента в
самом SQL нужно удваивать**, иначе драйвер примет его за плейсхолдер:

```sql
WHERE is_active AND %(q)s <%% search_name
```

## 5.5. Жизненный цикл приложения

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    db_pool.open()
    db_pool.wait(timeout=30)
    ensure_schema()
    print(f"[АББ] фронтенд: {FRONTEND_DIR} -> ...", flush=True)
    yield                       # ← здесь приложение работает
    db_pool.close()
```

> **Где это в коде:** `api/app/main.py:82` — `lifespan`;
> `api/app/main.py:55` — `ensure_schema`.

Всё до `yield` выполняется при старте, после — при остановке. Здесь мы
открываем пул, ждём доступности базы (`wait` — контейнер API может стартовать
раньше Postgres) и применяем миграции.

`flush=True` — сразу писать в лог, не копить в буфере. В контейнере без этого
сообщения появляются с задержкой.

### Миграции при старте

```python
SEARCH_SCHEMA_SQL = [
    r"""ALTER TABLE companies ADD COLUMN IF NOT EXISTS search_name TEXT
        GENERATED ALWAYS AS (lower(regexp_replace(name, '^(ООО|АО|...)\s+', ''))) STORED""",
    """CREATE INDEX IF NOT EXISTS companies_search_prefix ON companies (search_name text_pattern_ops)""",
]

def ensure_schema() -> None:
    global SEARCH_SCHEMA_READY
    try:
        with db_pool.connection() as conn, conn.cursor() as cur:
            for stmt in SEARCH_SCHEMA_SQL:
                cur.execute(stmt)
        SEARCH_SCHEMA_READY = True
    except Exception as e:
        print(f"[АББ] не удалось применить миграцию: {e}", flush=True)

    for path, title in ((GROUPS_SQL_FILE, "группы компаний"),
                        (LIMITS_SQL_FILE, "лимиты и заявки"),
                        (RESERVES_SQL_FILE, "резервы РСБУ и МСФО")):
        if not path.is_file():
            continue
        try:
            with db_pool.connection() as conn, conn.cursor() as cur:
                cur.execute(path.read_text(encoding="utf-8"))
        except Exception as e:
            print(f"[АББ] миграция «{title}» не применилась: {e}", flush=True)
```

Это прямое следствие ошибки, описанной в лекции 3: скрипты из `db/` выполняются
только на пустом томе. Теперь схема доводится до нужного состояния при каждом
запуске. Работает благодаря идемпотентности.

`r"""..."""` — «сырая» строка: `\s` внутри останется как есть, а не будет
принят Python за escape-последовательность.

## 5.6. Эндпоинт поиска

```python
PREFIX_SQL = """
SELECT id, name, inn, kpp, industry, 1.0::float AS score
FROM companies
WHERE is_active AND search_name LIKE %(prefix)s
ORDER BY search_name USING ~<~
LIMIT %(limit)s
"""

FUZZY_SQL = """
SELECT id, name, inn, kpp, industry, word_similarity(%(q)s, search_name)::float AS score
FROM companies
WHERE is_active AND %(q)s <%% search_name
ORDER BY score DESC, name
LIMIT %(limit)s
"""

@app.get("/api/companies")
def search_companies(query: str = Query(..., alias="q", min_length=3), limit: int = 8):
    params = {"q": query.lower(), "prefix": f"{query.lower()}%", "limit": limit}

    rows = db_query(INN_SQL, params) if query[:1].isdigit() else db_query(PREFIX_SQL, params)

    if len(rows) < 3:
        seen = {r["id"] for r in rows}
        for r in db_query(FUZZY_SQL, params):
            if r["id"] not in seen:
                rows.append(r)
        rows = rows[:limit]

    return to_jsonable(rows)
```

> **Где это в коде:** `api/app/main.py:137` — тексты запросов;
> `api/app/main.py:167` — обработчик `search_companies`.

Логика в три шага:

1. Начинается с цифры — ищем по ИНН, иначе по названию. Дешёвая эвристика,
   экономящая запрос.
2. Префиксный запрос — 0,08 мс.
3. Нашлось меньше трёх — дополняем нечётким поиском (64 мс). Он дорогой,
   поэтому запускается редко.

`seen = {r["id"] for r in rows}` — множество (set). Проверка `in` в нём
работает за константное время, в списке — за линейное.

### Демонстрация: SQL-инъекция вживую

Классическая атака: вместо ИНН пользователь вводит `' OR '1'='1`.

**Склейка строк — так делать нельзя:**

```python
evil = "' OR '1'='1"
bad = f"SELECT count(*) FROM companies WHERE inn = '{evil}'"
cur.execute(bad)
```

```
запрос: SELECT count(*) FROM companies WHERE inn = '' OR '1'='1'
вернулось строк: 28   ← вся таблица вместо нуля
```

**Параметризация — так правильно:**

```python
cur.execute("SELECT count(*) FROM companies WHERE inn = %s", (evil,))
```

```
запрос: SELECT count(*) FROM companies WHERE inn = %s   параметр: "' OR '1'='1"
вернулось строк: 0   ← как и должно быть
```

**Что произошло.** В первом случае кавычка из ввода закрыла строковый литерал,
а дальнейший текст стал **частью команды**: условие превратилось в
`inn = '' OR '1'='1'`, а `'1'='1'` истинно всегда. Вернулись все 28 компаний.

Во втором случае драйвер отправляет текст запроса и значение **раздельно**.
Для базы `' OR '1'='1` — это просто строка, которую надо сравнить с колонкой
`inn`. Совпадений нет, ответ ноль.

Здесь это выглядит безобидно — вернулось на 28 строк больше. В реальности
тем же приёмом вытаскивают чужие данные и удаляют таблицы. Правило простое:
**значение никогда не попадает в текст запроса**, только через параметр.

## 5.7. Преобразование данных для JSON

```python
def decimal_to_float(v):
    return float(v) if isinstance(v, Decimal) else v

def to_jsonable(rows: list[dict]) -> list[dict]:
    return [{k: decimal_to_float(v) for k, v in r.items()} for r in rows]
```

Postgres возвращает `NUMERIC` как `Decimal` — тип с точной арифметикой,
который стандартный сериализатор JSON не умеет. Переводим во `float` на
границе API.

Компромисс осознанный: во `float` теоретически возможна потеря точности на
больших суммах. Для отображения это несущественно, но **вычисления должны
оставаться в базе**, где тип `NUMERIC`. Считать деньги во float в Python —
плохая идея.

Даты тоже требуют внимания:

```python
r["valid_until"] = r["valid_until"].isoformat() if r["valid_until"] else None
```

`isoformat()` даёт `"2027-01-01"` — строку, понятную и JSON, и JavaScript.

## 5.8. Группировка на стороне API

База возвращает плоские строки, интерфейсу нужна структура. Собираем её в API:

```python
blocks = [
    {
        "code": code,
        "title": title,
        "items": [r for r in rows if r["block"] == code],
    }
    for code, title in BLOCK_TITLES.items()
]
return {
    "blocks": [b for b in blocks if b["items"]],
    "unified": {"sublimit": total, "utilized": used, "available": total - used},
    "applications": applications,
    "total": total,
    "used": used,
}
```

Почему здесь, а не в браузере: форма ответа — часть контракта API. Любой
клиент (браузер, мобильное приложение, отчётный скрипт) получит одинаковую
структуру и не будет повторять логику группировки.

Обратите внимание на `unified` — «единый сублимит» считается, а не хранится:

```python
total = sum(r["limit_amount"] for r in rows)
```

Это прямое следствие определения из глоссария: единый сублимит есть
совокупность лимитов клиента. Хранили бы отдельно — рано или поздно разошлось
бы со слагаемыми.

## 5.9. Кэш: как подключать необязательную зависимость

```python
class Cache:
    def __init__(self, url: str | None):
        self.enabled = False
        self._r = None
        if not url:
            return
        try:
            import redis
            self._r = redis.Redis.from_url(url, socket_timeout=0.3)
            self._r.ping()
            self.enabled = True
        except Exception as e:
            log.warning("Redis недоступен, работаем без кэша: %s", e)

    def get(self, key: str):
        if not self.enabled:
            return None
        try:
            raw = self._r.get(key)
            return json.loads(raw) if raw else None
        except Exception:
            return None
```

Приём — **graceful degradation**: если Redis не задан или недоступен,
приложение работает без него, а не падает. Каждый метод проверяет `enabled` и
глушит ошибки. Кэш — ускоритель, а не условие работы; ошибка в нём не должна
ронять запрос.

`socket_timeout=0.3` обязателен: без него недоступный Redis подвесит запрос
на десятки секунд.

## 5.10. Раздача фронтенда и заголовки кэширования

```python
FRONTEND_DIR = Path(os.getenv("WEB_DIR", "/srv/web"))
FRONTEND_AVAILABLE = (FRONTEND_DIR / "index.html").is_file()

if FRONTEND_AVAILABLE:
    app.mount("/", StaticFiles(directory=FRONTEND_DIR, html=True), name="web")
else:
    @app.get("/", response_class=HTMLResponse)
    def frontend_missing_page():
        return "<html>...инструкция, что проверить...</html>"
```

`mount("/")` объявляется **последним**: маршруты проверяются по порядку, и
монтирование корня перехватило бы `/api/*`, объявленные ниже.

Если папки нет, вместо голого 404 отдаётся страница с инструкцией — мы
потратили на этот 404 время, когда фронтенд не был примонтирован.

```python
@app.middleware("http")
async def no_cache_html(request, call_next):
    response = await call_next(request)
    if response.headers.get("content-type", "").startswith("text/html"):
        response.headers["Cache-Control"] = "no-store, must-revalidate"
    return response
```

> **Где это в коде:** `api/app/main.py:101` — `no_cache_html`;
> `api/app/main.py:474` — монтирование статики последним правилом.

**Middleware** — прослойка, через которую проходит каждый запрос. Здесь
запрещаем браузеру кэшировать HTML. Приём `?v=...` на css и js работает только
если сам `index.html` свежий, поэтому его кэшировать нельзя.

**Разбор:**

- **404** возвращает наш код: `raise HTTPException(404, "Компания не найдена")`.
- **422** возвращает FastAPI сам, ещё до входа в функцию: в объявлении стоит
  `Query(..., min_length=3)`. Писать проверку руками не нужно.
- `unified` в ответе по лимитам **посчитан**, а не прочитан из таблицы:
  4 132 423 457,79 — это сумма семи лимитов обоих блоков.
- Размеры ответов полезны как ориентир: три килобайта показателей — это
  22 показателя × 4 года. Если ответ вдруг вырастет в разы, что-то отдаётся
  лишнее.

## 5.13. Чего в бэкенде нет и что добавлять первым

Честный список пробелов прототипа:

1. **Аутентификация и авторизация.** Сейчас любой, кто открыл адрес, видит всё.
   Первое, что добавляется перед реальной эксплуатацией.
2. **Ограничение частоты запросов.** Нет защиты от перебора.
3. **Журнал действий.** Кто что смотрел — не фиксируется, для банка обязательно.
4. **Тесты.** Мы проверяли через `TestClient` вручную; нужен `pytest`.
5. **Пагинация.** Списки возвращаются целиком; на больших объёмах нужны страницы.

SQL-инъекция: ввод `' OR '1'='1` меняет смысл запроса. При параметризации (`%s`, `%(name)s`) драйвер передаёт значение отдельно от текста команды, и оно не может стать её частью.

</details>

**2. Зачем пул соединений?**

<details>
<summary>Показать ответ</summary>

Установка соединения с Postgres стоит миллисекунды и ресурсы. Пул держит их наготове: десяти соединений хватает на сотню пользователей, потому что каждый запрос занимает соединение всего на 2 мс.

</details>

**3. Что делает `lifespan` и почему миграции применяются там?**

<details>
<summary>Показать ответ</summary>

Код до `yield` выполняется при старте, после — при остановке. Миграции там, потому что файлы из `db/` не применяются к существующему тому, а при старте API схема гарантированно доводится до нужного состояния.

</details>

**4. Почему `Decimal` превращаем во `float` и где так делать нельзя?**

<details>
<summary>Показать ответ</summary>

Стандартный сериализатор JSON не умеет `Decimal`. Преобразование допустимо на границе API — для отображения. Считать деньги во `float` в Python нельзя, вычисления остаются в базе, где тип `NUMERIC`.

</details>

**5. Почему `app.mount("/")` должен идти последним?**

<details>
<summary>Показать ответ</summary>

Маршруты проверяются по порядку. Монтирование корня перехватывает все пути, включая `/api/*`, если они объявлены ниже.

</details>

**6. Зачем `db_pool.wait(timeout=30)` при старте?**

<details>
<summary>Показать ответ</summary>

Контейнер API может подняться раньше Postgres. Без ожидания первый же запрос упадёт с ошибкой соединения.

</details>

**7. Что такое graceful degradation на примере кэша?**

<details>
<summary>Показать ответ</summary>

Если Redis не задан или недоступен, приложение работает без него: каждый метод `Cache` проверяет флаг `enabled` и глушит ошибки. Кэш — ускоритель, а не условие работы.

</details>

**8. Зачем middleware с `Cache-Control: no-store` для HTML?**

<details>
<summary>Показать ответ</summary>

Приём `?v=...` у css и js работает, только если сам `index.html` свежий. Если браузер закэширует HTML, он продолжит запрашивать старые версии ресурсов.

</details>

**9. Что показывает `/api/health` и зачем столько полей?**

<details>
<summary>Показать ответ</summary>

Жива ли база, применены ли миграции (`search_schema`), работает ли кэш, смонтирован ли фронтенд (`web_mounted`). Каждое поле появилось после конкретной проблемы, на диагностику которой уходило время.

</details>

**10. Почему поиск по ИНН и по названию разведён на два запроса?**

<details>
<summary>Показать ответ</summary>

Дешёвая эвристика: если строка начинается с цифры, это ИНН. Так каждый запрос идёт по своему индексу вместо одного универсального с `OR`, который индексы использует хуже.

</details>
