# Лекция 1. Архитектура и стек

## 1.1. Что мы вообще построили

Лимитный модуль АББ — это **веб-приложение**: программа, которая живёт на сервере,
а пользователь работает с ней через браузер. У неё три слоя, и это самая важная
схема во всём курсе:

```
┌───────────────────────┐
│  БРАУЗЕР (клиент)     │   HTML + CSS + JavaScript
│  рисует интерфейс     │   сам ничего не хранит
└───────────┬───────────┘
            │ HTTP-запросы: GET /api/companies?q=маг
            ▼
┌───────────────────────┐
│  API (сервер)         │   Python + FastAPI
│  бизнес-логика        │   решает, что можно отдать и в каком виде
└───────────┬───────────┘
            │ SQL-запросы: SELECT ... FROM companies WHERE ...
            ▼
┌───────────────────────┐
│  БАЗА ДАННЫХ          │   PostgreSQL
│  хранит всё           │   единственный источник истины
└───────────────────────┘
```

Читать её нужно так: **браузер ничего не знает о базе**, а **база ничего не знает
о браузере**. Между ними стоит API — переводчик. Браузер говорит на HTTP, база —
на SQL, API умеет и то, и другое.

Зачем такое разделение? Три причины:

1. **Безопасность.** Если бы браузер ходил в базу напрямую, пароль от базы лежал
   бы в JavaScript, который каждый может открыть через «Просмотр кода страницы».
2. **Контроль.** API решает, что показывать. Браузер просит «данные компании 5» —
   API проверяет, можно ли, и отдаёт только разрешённые поля.
3. **Заменяемость.** Захотите мобильное приложение — оно обратится к тому же API.
   Захотите сменить Postgres на что-то другое — браузер этого даже не заметит.

## 1.2. Ключевые определения

Без этих слов дальше будет непонятно.

**HTTP** — протокол, язык общения браузера и сервера. Запрос состоит из метода
(`GET` — «дай», `POST` — «прими»), адреса (`/api/companies`) и, иногда, тела.
Ответ — из кода состояния (`200` — успех, `404` — не найдено, `500` — сервер
сломался) и тела.

**URL** — адрес: `http://localhost:8000/api/companies?q=маг&limit=8`
- `http` — протокол
- `localhost` — хост (эта же машина)
- `8000` — порт (номер «двери» на машине; на одной машине много программ, порт
  говорит, к какой именно стучимся)
- `/api/companies` — путь
- `?q=маг&limit=8` — query string, параметры запроса

**JSON** — текстовый формат обмена данными. Выглядит как объект JavaScript:

```json
{"id": 2, "name": "Магнитогорский МК", "inn": "7414003633"}
```

API отдаёт JSON, браузер его разбирает и рисует. Именно поэтому в проекте нет
ни одной серверной HTML-страницы: сервер отдаёт **данные**, а разметку строит
браузер.

**REST** — стиль проектирования API, где адрес обозначает ресурс, а метод —
действие над ним. У нас честный REST:

```
GET /api/companies?q=маг            найти компании
GET /api/companies/2                карточка компании 2
GET /api/companies/2/limits         лимиты компании 2
GET /api/companies/2/reserves       резервы компании 2
```

**SQL** — язык запросов к реляционной базе. `SELECT name FROM companies WHERE id = 2`.

**Контейнер** — изолированная коробка с программой и всем, что ей нужно для
работы. Разбирается в лекции 6.

## 1.3. Стек и почему именно он

Стек — это набор технологий. Наш:

| Слой | Технология | Почему |
|---|---|---|
| База | PostgreSQL 16 | Бесплатна, надёжна, умеет полнотекстовый и нечёткий поиск «из коробки» (`pg_trgm`) |
| Бэкенд | Python + FastAPI | Мало кода, автоматическая документация, асинхронность |
| Драйвер БД | psycopg 3 | Официальный драйвер Postgres для Python |
| Фронтенд | HTML + CSS + чистый JavaScript | Нет сборки, нет зависимостей, любой файл открывается и правится напрямую |
| Кэш | Redis (опционально) | Стоит в стеке, но не используется — почему, ниже |
| Веб-сервер | nginx (опционально) | Раздача статики и проксирование |
| Упаковка | Docker + Docker Compose | Одна команда поднимает всё окружение |

### Почему чистый JavaScript, а не React

React, Vue, Angular — популярные библиотеки. Мы их не взяли сознательно:

- **Сборка.** React требует Node.js, npm, сборщика (Vite/Webpack). Это ещё один
  слой, который надо ставить, обновлять и чинить. У нас правка в `styles.css`
  сразу видна после F5.
- **Размер.** React + ReactDOM — около 140 КБ. Весь наш фронтенд меньше.
- **Обучение.** Вы просили научить, как всё устроено. React прячет работу с DOM
  за абстракциями; здесь вы видите каждый `appendChild`.

Обратная сторона честная: при росте проекта ручное управление состоянием
станет утомительным. Признак, что пора переходить: когда одно изменение
требует править состояние в трёх местах и вы начинаете забывать, в каких.

### Почему отказались от кэша в Redis

Это хороший пример того, как решения принимаются по замерам, а не по привычке.
Мы собирались держать справочник компаний в Redis и обновлять раз в час.
Замерили на 200 000 компаний:

| Операция | Postgres | Снимок в Redis |
|---|---|---|
| Префиксный поиск, есть совпадения | 0,08 мс | 0,10 мс |
| Поиск без совпадений | 0,08 мс | **45 мс** |
| Разбор снимка при обновлении | — | 459 мс |

Кэш оказался в 560 раз медленнее базы в самом частом сценарии — пользователь
печатает и половина префиксов ничего не находит. Причина: Postgres идёт по
индексу за `log(n)` шагов, а перебор списка в памяти линеен. Redis остался в
проекте как опциональный сервис, но поиск ходит прямо в базу.

**Вывод, который стоит запомнить:** кэш ускоряет только то, что медленно.
Кэшировать индексированный запрос — значит заменить быстрое на медленное.

## 1.5. Путь одного запроса целиком

Проследим, что происходит, когда пользователь печатает «маг» в поиске.
Это самый полезный маршрут для понимания всей системы.

**Шаг 1. Браузер, `search-bar.js`** (`web/js/search-bar.js:19` — таймер
debounce)**.** Событие `input` на поле ввода. Меньше
3 символов — ничего не делаем. Есть 3 — ставим таймер на 160 мс (debounce,
лекция 4), чтобы не слать запрос на каждую букву.

**Шаг 2. Браузер, `api.js`** (`web/js/api.js:42` — сборка адреса)**.**
Таймер сработал:

```javascript
fetch('/api/companies?q=%D0%BC%D0%B0%D0%B3&limit=8')
```

Обратите внимание: «маг» превратилось в `%D0%BC%D0%B0%D0%B3`. Это
процентное кодирование — в адресе разрешены только ASCII-символы. Браузер
делает это сам через `encodeURIComponent`.

**Шаг 3. Сеть.** Уходит HTTP-запрос на `localhost:8000`.

**Шаг 4. Сервер, uvicorn.** Разбирает HTTP и передаёт FastAPI.

**Шаг 5. Сервер, FastAPI.** По пути `/api/companies` находит функцию
`search_companies`, вытаскивает из URL параметры, проверяет типы.

**Шаг 6. Сервер, `main.py`.** Функция выполняет SQL
(`api/app/main.py:167` — обработчик, `api/app/main.py:137` — текст запроса):

```sql
SELECT id, name, inn, kpp, industry, 1.0::float AS score
FROM companies
WHERE is_active AND search_name LIKE 'маг%'
ORDER BY search_name USING ~<~
LIMIT 8
```

**Шаг 7. База.** Идёт по btree-индексу, находит первые 8 строк, возвращает.
0,08 мс на 200 000 записей.

**Шаг 8. Сервер.** Превращает строки в список словарей, FastAPI сериализует
их в JSON и отдаёт с кодом 200.

**Шаг 9. Браузер, `api.js`.** `await response.json()` — JSON стал массивом
объектов JavaScript.

**Шаг 10. Браузер, `search-bar.js`** (`web/js/search-bar.js:18` — счётчик
запросов, `web/js/search-bar.js:79` — подсветка совпадения)**.** Проверяет номер запроса (не устарел ли
ответ), строит HTML подсказок, вставляет в DOM.

**Шаг 11.** Пользователь видит список. Прошло около 200 мс, из которых
160 — наш собственный debounce.

Все дальнейшие лекции — детализация этих одиннадцати шагов.

### Демонстрация: один запрос на всех четырёх слоях

Проследим «маг» через систему, глядя на настоящие ответы каждого слоя.

**Слой 1 — браузер отправляет:**

```
GET /api/companies?q=%D0%BC%D0%B0%D0%B3&limit=8
```

«маг» закодировано как `%D0%BC%D0%B0%D0%B3`: в адресе допустимы только
ASCII-символы, браузер кодирует сам.

**Слой 2 — API выполняет SQL:**

```sql
SELECT id, name, inn, kpp, industry, 1.0::float AS score
FROM companies
WHERE is_active AND search_name LIKE 'маг%'
ORDER BY search_name USING ~<~
LIMIT 8
```

**Слой 3 — база отвечает:**

```
 id |       name        |    inn     |    search_name
----+-------------------+------------+-------------------
  1 | Магнит            | 2309085638 | магнит
  2 | Магнитогорский МК | 7414003633 | магнитогорский мк
```

**Слой 4 — API отдаёт JSON:**

```json
[
  {"id": 1, "name": "Магнит", "inn": "2309085638", "kpp": "230901001",
   "industry": "Розничная торговля", "score": 1.0},
  {"id": 2, "name": "Магнитогорский МК", "inn": "7414003633", "kpp": "745501001",
   "industry": "Металлургия", "score": 1.0}
]
```

**Что изменилось на каждой границе:**

| Граница | Формат данных |
|---|---|
| Браузер → HTTP | текст адреса с процентным кодированием |
| API → база | SQL-команда с параметром |
| База → API | строки таблицы (в Python — список словарей) |
| API → браузер | JSON |
| Браузер → экран | узлы DOM |

Пять представлений одних и тех же данных. Каждый переход — место, где всё
может сломаться, и лекция 7 разбирает эти «швы» отдельно.

## 1.6. Как принимались решения

Несколько правил, которые стоят за проектом. Они важнее конкретного кода.

**Источник истины один.** Данные живут в Postgres. Всё остальное —
представления. Как только появляется вторая копия данных, появляется и
вопрос «какая из них правильная».

**Считать, а не хранить.** «Единый сублимит» по глоссарию — совокупность
лимитов клиента. Мы его не храним отдельно, а считаем суммой. Хранили бы —
рано или поздно сумма разошлась бы со слагаемыми.

**Замерять, а не угадывать.** История с Redis выше. Ещё пример: запрос
подсказок ускорился в 130 раз (10,2 мс → 0,08 мс) от одной строчки
`ORDER BY ... USING ~<~`. Без `EXPLAIN ANALYZE` это не найти.

**Идемпотентность.** Каждая миграция может быть выполнена повторно без
вреда. `ADD COLUMN IF NOT EXISTS`, `ON CONFLICT DO NOTHING`. Это позволяет
применять их при каждом старте API и не думать «а накатывали ли мы её».

**Явные ошибки лучше тихих.** Когда фронтенд не мог достучаться до бэкенда,
он молча переключался на демо-данные — и пользователь принимал выдуманные
цифры за настоящие. Добавили заметный жёлтый значок «демо-данные».

**2. Что означает код 404 и чем отличается от 500?**

<details>
<summary>Показать ответ</summary>

404 — «сервер работает, но такого ресурса нет»: ошибка на стороне запроса. 500 — «сервер сломался при обработке»: ошибка на стороне сервера. У нас 404 отдаётся, когда компания не найдена; 500 мы видели, когда код обращался к несуществующей колонке `search_name`.

</details>

**3. Что такое порт и зачем в адресе `localhost:8000` число 8000?**

<details>
<summary>Показать ответ</summary>

На одной машине работает много программ. Порт — номер «двери», по которому операционная система понимает, какой программе адресован пакет. У нас 8000 — API, 5433 — Postgres (наружу), 8080 — nginx в профиле full.

</details>

**4. Что такое REST и в чём его идея на нашем примере?**

<details>
<summary>Показать ответ</summary>

Адрес обозначает ресурс, метод — действие. `GET /api/companies/2/limits` читается как «дай лимиты компании 2». Не нужно придумывать имена вроде `getCompanyLimits` — структура адреса сама описывает данные.

</details>

**5. Почему кэш может замедлить систему?**

</details>

</details>
