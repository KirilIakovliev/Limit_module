# Лекция 2. Интерфейс: HTML, CSS и приёмы вёрстки

## 2.1. HTML — скелет

HTML описывает **структуру** документа. Он состоит из тегов:

```html
<div class="tab">Текст</div>
```

- `<div>` — открывающий тег, `</div>` — закрывающий
- `class="tab"` — атрибут; классы нужны, чтобы CSS и JS могли найти элемент
- «Текст» — содержимое

Теги вкладываются друг в друга и образуют дерево — **DOM** (Document Object
Model). Браузер строит это дерево из текста файла, а JavaScript потом его меняет.

### Атрибуты, которыми мы пользуемся

- `id="searchInput"` — уникальное имя. По нему JS находит элемент:
  `document.getElementById('searchInput')`
- `class="tab is-active"` — классов может быть несколько через пробел
- `data-company-id="20"` — собственный атрибут. Всё, что начинается с `data-`,
  разрешено придумывать самому; в JS читается как `node.dataset.companyId`
- `hidden` — элемент не отображается
- `aria-*` — подсказки для программ чтения с экрана

### Разбор нашего `index.html`

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Лимитный модуль АББ</title>
  <link rel="stylesheet" href="css/styles.css?v=20260827-1530">
</head>
<body>
  ...
  <script src="js/format.js?v=..."></script>
</body>
</html>
```

Построчно:

- `<!DOCTYPE html>` — «это современный HTML». Без него браузер включает режим
  совместимости с 1990-ми и вёрстка едет.
- `lang="ru"` — язык. Влияет на переносы слов и на голос синтезатора речи.
- `charset="utf-8"` — кодировка. Без неё кириллица превращается в «Ð›Ð¸Ð¼Ð¸Ñ‚».
- `viewport` — на телефоне не притворяться широким экраном. Без этой строки
  мобильная вёрстка не работает вообще.
- `<link rel="stylesheet">` — подключение CSS.
- `?v=20260827-1530` — **обход кэша**. Браузер хранит копию файла и может
  показывать старую версию после правок. Меняется номер версии — меняется
  адрес — браузер вынужден скачать заново. Мы натыкались на это в проекте:
  интерфейс выглядел старым, хотя файлы были новыми.
- `<script>` в конце `<body>` — чтобы к моменту выполнения скриптов элементы
  уже существовали в DOM.

### Порядок подключения скриптов

```html
<script src="js/format.js"></script>      <!-- 1. ни от кого не зависит -->
<script src="js/demo-data.js"></script>   <!-- 2. использует Format       -->
<script src="js/api.js"></script>         <!-- 3. использует DemoData     -->
...
<script src="js/app.js"></script>         <!-- последний: связывает всё   -->
```

Обычные (не-модульные) скрипты выполняются **по порядку**, и всё объявленное
через `const Format = ...` попадает в глобальную область. Поэтому порядок
важен: `api.js` не может идти раньше `demo-data.js`.

## 2.2. CSS — внешний вид

CSS состоит из правил:

```css
.tab-value {          /* селектор: к чему применяем */
  font-size: 15px;    /* свойство: значение          */
  color: #0F1D2B;
}
```

### Селекторы, которые встречаются в проекте

| Запись | Значение |
|---|---|
| `.tab` | все элементы с классом `tab` |
| `#companyTabs` | элемент с таким id |
| `.tab.is-active` | элементы, у которых **оба** класса |
| `.tab .tab-value` | `tab-value` **внутри** `tab` (на любой глубине) |
| `#companyTabs > .tab` | `tab` — **прямой ребёнок** `companyTabs` |
| `.tab:hover` | когда курсор над элементом |
| `.tab::before` | псевдоэлемент — «призрачный» блок внутри |
| `.tab:first-child` | первый среди соседей |
| `.tab:not(.is-active)` | все, кроме активных |

### Каскад и специфичность

Когда два правила спорят за одно свойство, побеждает более **специфичное**:
id (100) > класс (10) > тег (1). При равной специфичности побеждает то, что
**ниже** в файле.

Это не теория. В проекте был ровно такой баг: после переделки в файле остался
старый блок правил, и он шёл ниже нового:

```css
.tab-tree.branch-right .tab-branch::before{right:0}          /* новое */
...
.tab-tree.branch-right .tab-branch::before{left:calc(...)}   /* старое, ниже */
```

Специфичность одинаковая, поэтому победило старое — и черта-указатель
рисовалась слева вместо права. Лечение: удалить мёртвые правила.
**Если что-то стилизовано «не так», ищите второе правило ниже по файлу.**

### Переменные CSS

```css
:root {
  --navy: #123A63;
  --radius-pill: 999px;
}
.search-button { background: var(--navy); }
```

> **Где это в коде:** `web/css/styles.css:8` — блок `:root` с палитрой и радиусами;
> `web/css/styles.css:27` — градиент активной вкладки `--gradient-tab`.

`:root` — корень документа. Переменные наследуются вниз по дереву, поэтому их
можно переопределять локально:

```css
.tab-tree { --marker-gutter: 76px; }
@media (max-width: 1340px) {
  .tab-tree { --marker-gutter: 64px; }   /* на узком экране другое значение */
}
```

> **Где это в коде:** `web/css/styles.css:214` — объявление
> `.tab-tree{--marker-gutter:76px;--row-capacity:5}`; `web/css/styles.css:612` —
> медиазапрос `@media (max-width:1340px)`, переопределяющий отступ в 64px;
> `web/js/tab-tree.js:278` — функция `cssPx`, читающая значение;
> `web/js/tab-tree.js:396` — её вызов внутри `layoutBranch`.
>
> Цепочка целиком: значение объявлено в CSS → медиазапрос меняет его в
> зависимости от ширины окна → JS читает уже актуальное и считает по нему
> положение строк. Ни одного числа продублировано не было.

Именно так у нас работает адаптивность отступов: JS читает
`getComputedStyle(treeRoot).getPropertyValue('--marker-gutter')` и получает
то значение, которое действует на текущей ширине экрана. **Одна настройка
живёт в одном месте.**

## 2.3. Блочная модель и размеры

Каждый элемент — прямоугольник из четырёх слоёв:

```
┌─ margin (внешний отступ) ──────────────┐
│ ┌─ border (рамка) ───────────────────┐ │
│ │ ┌─ padding (внутренний отступ) ──┐ │ │
│ │ │        content (содержимое)    │ │ │
│ │ └────────────────────────────────┘ │ │
│ └────────────────────────────────────┘ │
└────────────────────────────────────────┘
```

По умолчанию `width` задаёт только `content`, и рамка с отступами прибавляются
сверху — считать неудобно. Первое правило в нашем файле это исправляет:

```css
* { box-sizing: border-box; }
```

Теперь `width: 200px` — это вся ширина вместе с рамкой и padding.

## 2.4. Flexbox — раскладка в строку

Почти все ряды карточек у нас — flex-контейнеры.

```css
.tab-row {
  display: flex;              /* дети выстраиваются в строку     */
  justify-content: center;    /* выравнивание по главной оси     */
  align-items: stretch;       /* по поперечной: тянуть по высоте */
  gap: 12px;                  /* промежуток между детьми         */
  flex-wrap: wrap;            /* переносить, если не помещаются  */
}
```

У детей главное свойство — `flex`, это сокращение трёх:

```css
.tab { flex: 0 1 var(--tab-basis); }
/*          │ │ └ базовый размер                        */
/*          │ └── flex-shrink: можно ли сжимать (1 = да) */
/*          └──── flex-grow: можно ли растягивать (0 = нет) */
```

### Как мы добились одинаковой ширины карточек

Сначала было `flex: 1 1 0` — «разделите строку поровну». Проблема: строка из
4 карточек делила ширину на 4, строка из 5 — на 5, и карточки получались
разного размера в разных рядах.

Решение — считать ширину от **самого ёмкого** ряда:

```css
.tab-row {
  --tab-basis: calc((100% - (var(--row-capacity) - 1) * 12px) / var(--row-capacity));
}
.tab { flex: 0 1 var(--tab-basis); }
```

`--row-capacity: 5` — «в самом длинном ряду 5 карточек». Формула: из ширины
строки вычесть все промежутки и разделить на 5. Ряд из 3 карточек получает те
же по ширине карточки, просто занимает 3/5 строки.

### Проценты в `calc` внутри flex-basis

`100%` в `--tab-basis` считается от ширины **родителя** (строки) в момент
применения. Это работает, потому что переменная объявлена на `.tab-row`, а
используется у детей: подстановка текстовая, вычисление — в контексте ребёнка.

## 2.5. Grid — раскладка в таблицу

Структура ГК — это сетка из пяти равных колонок:

```css
.group-grid {
  display: grid;
  grid-template-columns: repeat(5, minmax(0, 1fr));
  gap: 12px;
}
```

- `1fr` — «одна доля свободного места»; пять таких колонок равны между собой
- `minmax(0, 1fr)` — важная деталь: без `minmax(0, ...)` колонка не может стать
  уже своего содержимого, и длинное слово ломает всю сетку

Каждый ряд компаний — отдельная сетка с теми же настройками, поэтому колонки
всех рядов выстраиваются друг под другом.

## 2.6. Анимации: два приёма

### Раскрытие уровня через grid-template-rows

Классическая беда: `height` нельзя плавно анимировать от нуля до «сколько
получится», потому что `height: auto` не число. Обходной приём:

```css
.tab-level {
  display: grid;
  grid-template-rows: 0fr;                /* закрыто */
  transition: grid-template-rows .48s;
}
.tab-level.is-open { grid-template-rows: 1fr; }   /* открыто */
.tab-level > * { overflow: hidden; min-height: 0; }
```

> **Где это в коде:** `web/css/styles.css:195` — правило `.tab-level`;
> `web/css/styles.css:77` — тот же приём для заголовка страницы (`.page-title-wrap`),
> который схлопывается при переходе к результатам.

`fr` — доля. `0fr` — нулевая высота, `1fr` — вся нужная. Между ними браузер
умеет анимировать. `overflow: hidden` на ребёнке обязателен, иначе содержимое
вылезет за пределы схлопнутой строки.

### Сдвиг строки через transform

```css
.tab-row { transition: transform .55s cubic-bezier(.22,.7,.2,1); }
```

Почему `transform: translateX(-56px)`, а не `left: -56px`? Потому что
`transform` обрабатывается видеокартой и не заставляет браузер пересчитывать
раскладку всей страницы. Правило: **анимируйте `transform` и `opacity`, всё
остальное — только когда иначе никак.**

> **Где это в коде:** `web/css/styles.css:261` — `.tab-row` с `transition: transform`;
> сам сдвиг назначает `web/js/tab-tree.js:385` (`layoutBranch`).

`cubic-bezier(.22,.7,.2,1)` — кривая скорости: быстрый старт, мягкое
торможение. Движение выглядит естественнее, чем равномерное.

### Пульсация стрелок

```css
@keyframes arrowPulse {
  0%, 100% { opacity: .14; }
  50%      { opacity: .72; }
}
.row-arrow { animation: arrowPulse 3.4s ease-in-out infinite; }
```

> **Где это в коде:** `web/css/styles.css:224` — `.row-arrow` (позиция и анимация);
> `web/css/styles.css:247` — сами кадры `@keyframes arrowPulse`;
> `web/js/tab-tree.js:362` — `placeArrows`, расставляющая стрелки по краям карточек.

`@keyframes` описывает кадры в процентах от длительности. Синхронность двух
стрелок обеспечивается тем, что анимация назначается им одновременно и с
одинаковой задержкой: при возврате в центр класс снимается с обеих сразу,
и отсчёт для обеих начинается заново.

## 2.7. Контекст наложения — самый коварный баг проекта

Симптом: выпадающий список подсказок оказывался **под** карточками
результатов, хотя у него `z-index: 30`, а у карточек ничего.

Причина: свойство `transform` создаёт **контекст наложения** (stacking
context). Внутри него `z-index` детей действует только относительно друг
друга, а сам контекст соревнуется с соседями как единое целое.

```
.hero          (есть transform → свой контекст)
   └─ .suggestions  z-index: 30    ← 30 действует только внутри .hero
.result-panel  (есть transform → свой контекст)
   └─ карточки
```

> **Где это в коде:** `web/css/styles.css:66` — `.hero` с `transform` и `z-index: 20`;
> `web/css/styles.css:161` — `.result-panel` с `z-index: 1`;
> `web/css/styles.css:141` — `.suggestions` с `z-index: 30`.

Оба контекста имеют `z-index: auto`, значит порядок определяется положением в
документе — `.result-panel` идёт ниже, поэтому рисуется поверх. Лечение —
задать порядок самим контекстам:

```css
.hero         { position: relative; z-index: 20; }
.result-panel { position: relative; z-index: 1; }
```

**Запомните:** `transform`, `filter`, `opacity < 1`, `will-change` создают
контекст наложения. Если `z-index` «не работает» — ищите такого родителя.

## 2.8. Тени, рамки и геометрия

```css
--shadow-tab: 2px 3px 6px rgba(18,58,99,.14),
              4px 8px 16px rgba(18,58,99,.16);
```

Формат: `смещение-X смещение-Y размытие цвет`. Можно перечислить несколько
теней через запятую — ближняя даёт чёткость, дальняя мягкость. Тень
автоматически повторяет `border-radius` элемента.

Отдельная ловушка, на которую мы наткнулись: у активной вкладки была
`border-color: transparent` поверх горизонтального градиента. Прозрачная
рамка **пропускает фон насквозь**, поэтому слева рамка выглядела тёмной, а
справа светлой. Два лечения:

```css
background-clip: padding-box;   /* фон не заходит под рамку */
border-color: #1B4E80;          /* явный цвет со всех сторон */
```

## 2.9. Размеры по содержимому: min-content и max-content

Это ключ к адаптивной ширине карточек.

- `max-content` — ширина текста, если запретить переносы вообще
- `min-content` — ширина самого длинного **неразрывного** слова

Для «Магнитогорский МК»: `max-content` ≈ 192px, `min-content` ≈ 165px
(«Магнитогорский»). Для ИНН `7414003633` они совпадают — в числе нет пробелов,
разорвать его нельзя.

На этом построен двухступенчатый подбор ширины верхней строки (реализация в
лекции 4): сначала пробуем `max-content` — весь текст в строку; не помещается —
берём `min-content`, тогда название переносится по пробелам, но ни слово, ни
число не рвутся.

Плюс страховка на крайний случай:

```css
.tab-value { overflow-wrap: break-word; }
```

Разрешает разорвать слово, только если оно не помещается никак.

## 2.10. Медиазапросы

```css
@media (max-width: 1340px) { .tab-tree { --marker-gutter: 64px; } }
@media (max-width: 1100px) { .tab-tree { --row-capacity: 3; } }
@media (max-width: 760px)  { .tab-tree { --row-capacity: 2; } }
```

Читается: «при ширине окна не больше 1340px применить эти правила».
Мы меняем не размеры напрямую, а **переменные** — и вся раскладка,
завязанная на них, перестраивается сама.

Ещё один важный запрос:

```css
@media (prefers-reduced-motion: reduce) {
  * { animation-duration: .01ms !important; transition-duration: .01ms !important; }
}
```

Часть людей отключает анимации в системе — от них укачивает. Уважать эту
настройку — норма.

## 2.11. Псевдоэлементы как инструмент

`::before` и `::after` создают элемент, которого нет в HTML. Обязателен
`content`, иначе не появится.

Черта-указатель раскрытого уровня:

```css
.tab-branch::before {
  content: "";
  position: absolute; top: 10px;
  width: 56px; height: 2px;
  background: var(--blue-400);
  display: none;
}
.tab-tree.branch-left  .tab-branch::before { display: block; left: 0; }
.tab-tree.branch-right .tab-branch::before { display: block; right: 0; }
```

Разделители в блоке ИНН/КПП — тоже псевдоэлементы:

```css
.tab-pair::before, .tab-pair::after {
  content: ""; position: absolute;
  top: 24%; height: 52%; width: 1px;
  background: var(--line);
}
.tab-pair::before { left: 0; }
.tab-pair::after  { right: 0; }
```

> **Где это в коде:** `web/css/styles.css:252` — черта уровня `.tab-branch::before`;
> `web/css/styles.css:345` — блок `.tab-pair` с разделителями по краям.

Высота 52% и отступ сверху 24% дают короткую черту по центру — визуально это
разделитель, а не рамка.

**4. Почему анимируем `transform`, а не `left`?**

<details>
<summary>Показать ответ</summary>

`transform` обрабатывается видеокартой и не вызывает пересчёт раскладки страницы. Изменение `left` заставляет браузер заново считать положение элементов на каждом кадре.

</details>

**5. У элемента `z-index: 999`, но он под соседом. Что проверить?**

<details>
<summary>Показать ответ</summary>

Есть ли у родителя `transform`, `filter`, `opacity < 1` или `will-change` — они создают контекст наложения, внутри которого `z-index` действует только относительно соседей. Лечится заданием `z-index` самим контекстам (`web/css/styles.css:66` и `161`).

</details>

**6. Чему равны `min-content` и `max-content` для «7414003633» и для «Магнитогорский МК»?**

<details>
<summary>Показать ответ</summary>

Для числа они совпадают: в нём нет пробелов, разрывать нечего. Для названия `max-content` ≈ 192px (вся фраза в строку), `min-content` ≈ 165px (самое длинное слово «Магнитогорский»).

</details>

**7. Зачем `box-sizing: border-box` в самом начале файла?**

<details>
<summary>Показать ответ</summary>

Чтобы `width` включал рамку и внутренние отступы. По умолчанию они прибавляются сверху, и `width: 200px` даёт элемент шириной 236px при padding 18px (`web/css/styles.css:46`).

</details>

**8. Почему у активной вкладки рамка выглядела разной слева и справа?**

<details>
<summary>Показать ответ</summary>

Была `border-color: transparent` поверх горизонтального градиента — прозрачная рамка пропускает фон насквозь. Лечится `background-clip: padding-box` и явным цветом рамки.

</details>

**9. Что делает `@media (prefers-reduced-motion: reduce)`?**

<details>
<summary>Показать ответ</summary>

Отключает анимации для тех, кто выключил их в системе — обычно из-за укачивания. Уважать эту настройку — норма доступности (`web/css/styles.css:648`).

</details>

**10. Зачем `?v=20260827-1530` в адресе стилей?**

<details>

Обход кэша браузера. Меняется версия — меняется адрес — файл скачивается заново. Без этого правки не видны, хотя файлы на сервере новые.

</details>
