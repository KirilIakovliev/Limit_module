# Spec: Лимитный модуль на копиях витрин DataHub

Зафиксировано: 2026-09-28. Источник истины по структуре — DDL команды данных. UI — как в прототипе, данные — из `t_lm_*`.

## Цель

Прототип читает изобретённую схему `public` (`companies.id`). Нужно читать PostgreSQL-копии итоговых витрин DataHub 1:1, не меняя дерево вкладок и поведение экрана без необходимости.

## Контракт данных

- БД `abb` / `limitmodule`: схемы `sbox_rsk_drt`, `srd`, `app`.
- **UI читает только** `t_lm_1_2_clients`, `t_lm_1_2_gk_info`, `t_lm_1_3_limits`, `t_lm_egar_limits` (+ `app.load_log` для свежести).
- `stg_file_*`, `srd.corpgen_*`, `t_util` лежат на том же сервере. Backend их не читает. Сборка зелёных витрин из серых **не реализована** (это слой DataHub / будущий job приложения).
- На копиях DataHub нет PK/FK/NOT NULL/DEFAULT. Ключ клиента — ИНН. Дедуп: `source=datahub` предпочтительнее `egar`.
- Единственное отклонение имени колонки: GAP G11 (`утилиз-й совокупный лимит на гк`). Подробно: `docs/ddl_conversion.md`.

## API (было → стало)

| Было | Стало |
|---|---|
| `GET /api/companies?q=` | `GET /api/clients?q=` |
| `GET /api/companies/{id}` | `GET /api/clients/{inn}` |
| `GET /api/companies/{id}/limits` | `GET /api/clients/{inn}/limits` |
| профиль / ГК из `id` | `GET /api/groups/{crm_id}` |
| `company_sync_log` | `GET /api/meta` ← `app.load_log` |

Удалены: `/indicators`, `/sublimits`, `/reserves`, `/profile` как отдельные источники. Сублимиты и резервы в UI — empty state.

## UI (что трогали намеренно)

- Привязка к ИНН, валюта строки, `rest_lim` из витрины, подсветка превышения, даты без сдвига зоны.
- Вкладки «События» и «Финансовая отчётность» скрыты (нет в БТ / нет в DDL).
- «Сублимиты», «Информация о резервах» — те же названия, заглушка «источник не подключён».
- Нет fallback на `demo-data.js`.

Не менять внешний вид вкладок и комментарии геометрии дерева без нужды.
